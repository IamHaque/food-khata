# E1 API implementation handoff

Implemented `create_app(db_path: Path | str, dev: bool = False, dist_path: Path | str | None = None) -> FastAPI`, serve dispatch, read-only transaction per request, bounded retry, loopback/host checks, static SPA restrictions, and an mtime/WAL-keyed dashboard cache. GET filters are repeated query parameters; POST dashboard accepts `Filters`. The generated synthetic OpenAPI JSON documents query parameters and response models. The endpoints expose masked account labels and scoped orders, metadata, health, dashboard, bills, slim orders and leaderboards.

Synthetic verification: `72 passed, 10 subtests passed` (plus one Starlette/httpx deprecation warning); tests cover scoped totals, masking, bounds, sort injection, 404, retry/503, cache invalidation and static data exclusion. CI installs the serve extra and httpx on its existing Python matrix. Run `python scripts/export_openapi.py` to regenerate the contract without database access.

Remaining before calling this complete: data-health does not yet provide null rates, duplicate or reconciliation anomaly statistics; the items leaderboard has no price trend; bill and order fields do not yet expose every stored financial component; aggregate price totals are not uniformly rounded; default FastAPI method-not-allowed errors are not in the required error envelope; connection/BEGIN busy failures are not retried; GET cannot explicitly express an empty statuses list; static assets are restricted to standard Vite assets and selected root files. Additional chart datasets beyond monthly remain for future work. Cache concurrency and WAL-specific invalidation require broader testing. No real database or real-data parity check was used.
